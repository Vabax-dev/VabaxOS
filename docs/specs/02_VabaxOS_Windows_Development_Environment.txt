VABAXOS
GUIDA ALL'AMBIENTE DI SVILUPPO ACCESSIBILE SU WINDOWS
Windows 11 + WSL2 + Ubuntu + Git + VS Code + QEMU

Versione documento: 1.0
Data: 23 settembre 2026
Progetto: VabaxOS

======================================================================
0. SCOPO
======================================================================

Questo documento prepara una workstation Windows per sviluppare VabaxOS
nel lungo periodo.

L'architettura scelta è:

Windows 11
    |
    +-- NVDA / accessibilità Windows
    |
    +-- Git / GitHub
    |
    +-- VS Code
    |
    +-- Windows Terminal / PowerShell
    |
    +-- QEMU
    |
    +-- WSL2
          |
          +-- Ubuntu 24.04 LTS
                |
                +-- GCC / Clang / LLVM
                +-- C / C++
                +-- Python
                +-- Rust
                +-- CMake / Ninja
                +-- Git
                +-- QEMU tools
                +-- x86-64 cross compilation
                +-- VabaxOS build system

PRINCIPIO FONDAMENTALE:

Windows è la workstation principale.
WSL2 è l'ambiente Linux di sviluppo.
QEMU è il laboratorio virtuale.
L'hardware fisico viene utilizzato soltanto dopo che una build è stata
verificata in virtualizzazione.

Questo evita di compromettere il PC principale durante le prime fasi.

======================================================================
1. PRIMA DI INIZIARE
======================================================================

Requisiti consigliati:

- Windows 11 aggiornato;
- CPU x86-64 con virtualizzazione hardware;
- almeno 16 GB RAM;
- almeno 100 GB liberi;
- preferibilmente SSD/NVMe;
- connessione Internet;
- account GitHub;
- NVDA aggiornato;
- cuffie o altoparlanti per testare TTS e audio.

Per il progetto completo è consigliabile avere più spazio.
Kernel, toolchain, sorgenti, cache, ISO, VM e repository possono crescere
rapidamente.

Non è necessario installare Linux in dual boot.

WSL2 fornisce un ambiente GNU/Linux integrato in Windows. Microsoft
raccomanda `wsl --install` per le installazioni moderne e WSL2 viene
impostato come default dalle installazioni attuali.
Fonte ufficiale:
https://learn.microsoft.com/windows/wsl/install

======================================================================
2. ACCESSIBILITÀ WINDOWS
======================================================================

Prima di costruire VabaxOS, l'ambiente di sviluppo deve essere
completamente utilizzabile con NVDA.

Verificare:

[ ] NVDA avvia correttamente.
[ ] Windows Terminal è navigabile.
[ ] PowerShell è utilizzabile.
[ ] Esplora file è utilizzabile.
[ ] VS Code è utilizzabile.
[ ] GitHub è utilizzabile.
[ ] Dialoghi di salvataggio sono accessibili.
[ ] Output del terminale viene letto correttamente.
[ ] Copia/incolla funziona.
[ ] Navigazione tra finestre funziona.

È consigliabile usare scorciatoie da tastiera il più possibile.

Per il progetto è importante che ogni procedura descritta in questo
documento possa essere eseguita senza mouse quando possibile.

======================================================================
3. WINDOWS TERMINAL
======================================================================

Windows Terminal sarà il punto di accesso principale a:

- PowerShell;
- WSL;
- eventualmente altre shell.

Aprire Windows Terminal.

Creare un profilo per Ubuntu/WSL se non viene creato automaticamente.

Impostazioni consigliate:

- font leggibile;
- dimensione adeguata;
- output non eccessivamente decorato;
- profilo facilmente raggiungibile da tastiera;
- copia/incolla funzionante.

Non usare configurazioni che nascondano errori o output del terminale.

======================================================================
4. INSTALLARE WSL2
======================================================================

Aprire PowerShell come amministratore.

Eseguire:

wsl --install

Riavviare Windows se richiesto.

La procedura ufficiale abilita i componenti necessari, installa il
kernel WSL e una distribuzione Linux predefinita.

Fonte:
https://learn.microsoft.com/windows/wsl/install

Dopo il riavvio verificare:

wsl --status

e:

wsl --version

Poi:

wsl --list --verbose

Dovrebbe comparire una distribuzione Linux con VERSION 2.

Se Ubuntu non è installato o si desidera specificarlo esplicitamente:

wsl --list --online

poi:

wsl --install -d Ubuntu-24.04

Se il nome disponibile è diverso, utilizzare il nome restituito da
`wsl --list --online`.

======================================================================
5. CONFIGURAZIONE WSL
======================================================================

Avviare Ubuntu.

Creare il proprio utente Linux quando richiesto.

Verificare:

whoami

hostname

uname -a

Verificare WSL da Windows:

wsl --list --verbose

Obiettivo:

Ubuntu    Running    2

Aggiornare:

sudo apt update
sudo apt upgrade

Riavviare WSL quando necessario:

wsl --shutdown

e poi riaprire Ubuntu.

Documentazione ufficiale:
https://learn.microsoft.com/windows/wsl/setup/environment

======================================================================
6. DOVE METTERE IL REPOSITORY
======================================================================

Per un progetto Linux pesante è preferibile lavorare principalmente nel
filesystem Linux di WSL anziché fare tutto sotto `/mnt/c`.

Directory consigliata:

~/projects/VabaxOS

Creazione:

mkdir -p ~/projects
cd ~/projects

Il repository sarà:

~/projects/VabaxOS

Windows può accedere ai file Linux tramite:

\\wsl$

ma il build principale deve essere eseguito dentro WSL.

Questo riduce problemi di performance e differenze di permessi.

8. RUST
======================================================================

Installare Rust tramite rustup:

curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

Seguire la procedura.

Ricaricare la shell:

source "$HOME/.cargo/env"

Verificare:

rustc --version

Rust non verrà usato ovunque.
Sarà disponibile per componenti nuovi in cui sicurezza della memoria,
concorrenza o robustezza lo rendano conveniente.

======================================================================
14. QEMU
======================================================================

QEMU sarà il laboratorio principale per VabaxOS.

Sito ufficiale:
https://www.qemu.org/

È possibile installare QEMU anche su Windows.
La pagina ufficiale di download pubblica le release disponibili.

Su Windows sarà utile soprattutto per lanciare rapidamente VM.

Dentro WSL possono inoltre essere installati gli strumenti QEMU:

sudo apt install -y qemu-system-x86 qemu-utils

Verificare:

qemu-system-x86_64 --version

La documentazione QEMU per Windows Hypervisor Platform descrive
l'accelerazione WHPX su Windows:
https://www.qemu.org/docs/master/system/whpx.html

======================================================================
16. TOOLCHAIN CROSS-COMPILAZIONE
======================================================================

VabaxOS sarà compilata per x86-64.

Anche se l'ambiente host fosse diverso, la toolchain deve essere
esplicitamente controllata.

Per il target iniziale:

x86_64

Componenti da controllare:

- gcc;
- binutils;
- clang;
- lld;
- nasm eventualmente;
- linker;
- assembler;
- libc del target quando necessario.

Non costruire una cross-toolchain completa manualmente finché non serve.

Prima verificare se la base scelta per VabaxOS fornisce già toolchain
adeguate.

La scelta definitiva della toolchain sarà documentata in
ARCHITECTURE.md.

======================================================================
17. KERNEL LINUX
======================================================================

Il kernel sarà compilato nel progetto quando arriveremo al build system.

NON scaricare e modificare casualmente il kernel nel repository.

Struttura prevista:

kernel/
    config/
    patches/
    scripts/

Il codice upstream del kernel potrà essere scaricato durante il build
oppure gestito tramite un meccanismo di source pinning.

Ogni versione del kernel utilizzata dovrà essere registrata.

Esempio:

Linux X.Y.Z

con:
- checksum;
- sorgente;
- patch;
- configurazione;
- motivazione della versione scelta.

======================================================================
18. BOOT E UEFI
======================================================================

VabaxOS v0.1 utilizzerà UEFI come target principale.

Dovranno essere disponibili strumenti per:

- EFI System Partition;
- filesystem FAT;
- immagini EFI;
- bootloader;
- initramfs;
- kernel.

Pacchetti utili già installabili in Ubuntu:

sudo apt install -y \
    grub-efi-amd64-bin \
    grub-pc-bin \
    dosfstools \
    mtools

La scelta definitiva tra systemd-boot e GRUB sarà registrata in un ADR.

======================================================================
19. BUILD SYSTEM
======================================================================

Il progetto dovrà arrivare a un comando riproducibile:

./build.sh

oppure:

./scripts/build.sh

Risultato:

build/
    VabaxOS-x86_64.iso

Il build system dovrà:

1. controllare dipendenze;
2. scaricare o verificare sorgenti;
3. preparare toolchain;
4. compilare kernel;
5. creare root filesystem;
6. installare userspace;
7. creare initramfs;
8. preparare UEFI;
9. creare ISO;
10. calcolare checksum;
11. produrre log.

Non usare comandi manuali diversi a ogni build.

45. NOTA FINALE
======================================================================

Questo documento non descrive soltanto come installare alcuni programmi.

Descrive l'ambiente di sviluppo permanente di VabaxOS.

La workstation Windows deve essere considerata:

    VABAXOS DEVELOPMENT STATION

Il sistema operativo che stiamo sviluppando sarà Linux, ma il computer
da cui lo sviluppiamo resterà Windows.

La separazione è intenzionale:

Windows
    = ambiente personale e workstation

WSL2
    = ambiente Linux di sviluppo

QEMU
    = laboratorio virtuale

Hardware reale
    = laboratorio di compatibilità

GitHub
    = sorgente ufficiale del progetto

Gemini
    = ricerca e QA

Claude
    = implementazione

Vabax
    = direzione e architettura

Il primo risultato concreto non sarà ancora un desktop.

Sarà una pipeline affidabile:

    SOURCE
      |
    BUILD
      |
    KERNEL
      |
    ROOTFS
      |
    ISO
      |
    QEMU
      |
    BOOT

Da quel momento VabaxOS potrà iniziare a essere costruito realmente.
